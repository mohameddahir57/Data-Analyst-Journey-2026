# Dec 18 — Complex Joins + Multiple Tables

So far we've mostly joined **two** tables. In the real world, you often need to join 3, 4, or even 10+ tables to get the data you need. Today we also cover special join types dealing with hierarchies and sets.

## 1. Joining Multiple Tables (Chaining Joins)
You can chain as many `JOIN` clauses as you need. The result of the first join becomes the "left" table for the second join, and so on.

**Scenario**: We want to see **Customer Name**, **Order Date**, and the **Products** they bought.
- `Customers` tells us the name.
- `Orders` tells us the date and links to Customer.
- `Order_Items` links Order to Product.
- `Products` tells us the product name.

**Syntax:**
```sql
SELECT c.name, o.order_date, p.name as product_name
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id;
```
*Tip: Always use aliases (c, o, oi, p) to keep your query readable.*

## 2. Self Joins
A **Self Join** is a regular join, but the table is joined with **itself**. This is common for hierarchical data stored in a single table, like Employees (where one column is `manager_id` pointing to another `employee_id` in the same table).

**Scenario**: List every employee's name and their manager's name.

**Syntax:**
```sql
SELECT 
    e.name AS employee_name, 
    m.name AS manager_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;
```
*Note: We use `LEFT JOIN` so that the CEO (who has no manager) still appears.*

## 3. CROSS JOIN (Cartesian Product)
A **CROSS JOIN** returns the combination of **every** row from the first table with **every** row from the second table.
- If Table A has 10 rows and Table B has 5 rows, the result is 10 * 5 = 50 rows.
- Be careful! This can create huge results on large tables.

**Use Case**: Generating all possible combinations (e.g., specific sizes for every color).

**Syntax:**
```sql
SELECT colors.color_name, sizes.size_name
FROM colors
CROSS JOIN sizes;
```

## 4. Set Operations: UNION vs UNION ALL
Joins combine columns (horizontally). Set operations combine rows (vertically) from two separate queries.
Both queries must have the **same number of columns** and compatible data types.

### UNION
Combines results and **removes duplicates**.
```sql
SELECT city FROM customers
UNION
SELECT city FROM suppliers;
```

### UNION ALL
Combines results and **keeps duplicates**. This is faster than UNION because it doesn't have to check for uniqueness.
```sql
SELECT city FROM customers
UNION ALL
SELECT city FROM suppliers;
```
